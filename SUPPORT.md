# Support

| You have | Go to |
|---|---|
| A bug in a product | That repository's issues, using the bug template. |
| A feature request | That repository's issues, using the feature template. |
| A question about using a product | That repository's Discussions if it has them, otherwise an issue. |
| A security vulnerability | [SECURITY.md](./SECURITY.md). Never a public issue. |
| A conduct concern | `conduct@redrob.ai`. See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md). |
| A question about how to contribute | [CONTRIBUTING.md](./CONTRIBUTING.md), then an issue. |
| Something about our client or platform work | [mckinley-and-rice](https://github.com/mckinley-and-rice), our other organization. |

Report it against the repository it happened in. If you are not sure which, pick the one you
were using and say so; moving an issue is cheap and guessing wastes your time as well as ours.

Ask in English or Korean, whichever you write more comfortably.

## Before you file

Two answers that resolve most reports faster than we can:

**Say which version.** "Latest" is not a version, and these products ship on several platforms
with separate installers. The version string is in the app's about panel or `--version`.

**Say whether it happens in a fresh profile.** A crash that only occurs in your existing profile
is a different bug from one that occurs in a new one, and knowing which halves the search. One
of these products shipped a self-propagating crash where a single force-quit left a flag that
killed every later launch, and it was only distinguishable this way.

## What we do not do

We do not provide support by direct message. A question answered in an issue is answered for
everyone who searches it later.

We do not have a commercial support contract for these repositories. They are maintained because
we use them.
